# SGU 日本本科选校工作台

换电脑或接续开发，请先阅读 [开发交接 HANDOFF.md](HANDOFF.md)。

面向公司升学顾问的内部工作台。三个入口共用一套经核对的项目规则：学生匹配、条件问答、学校与项目浏览；同时提供资料维护、团队共享、修改记录和版本回档。

首期内置立命馆大学 2027 AO 英语本科 GLA、JDP、GS、CRPS、ISSE 五个项目，28条语言考试／版本门槛和11组申请轮次。资料来自用户提供的23页手册及已核对的135条分析记录。原文及关键词库随源码提供，真实学生数据不会写入Git。

## 线上运行与发布

正式工作台：**https://sgu.up.railway.app/**。Railway运行应用，Supabase保存正式业务数据、原文件、提取文本及模型配置。上传、解析和整理全部在线完成，无需本机服务。后续采用“修改代码与隔离测试 → 推送main → 核对Railway部署 → 在线验证”的流程，常规修改直接发布，完整约定见[AGENTS.md](AGENTS.md)。

## 可选的独立开发环境

以下本机启动说明仅保留供隔离开发或恢复使用，不是日常工作入口或上线验收条件。测试不得使用正式数据库创建虚拟档案。

需要 **Node.js 24.15或以上**，使用Node原生HTTP、浏览器ES模块及`pg`数据库驱动，无前端构建步骤。配置`DATABASE_URL`时连接共享PostgreSQL，否则继续使用原生SQLite。

```powershell
git clone https://github.com/yangdyjp-glitch/SGU.git
cd SGU
npm.cmd ci
npm.cmd start
```

访问 **http://127.0.0.1:3210**。首次打开使用账号和密码创建管理员，不再填写姓名；随后在“团队设置”取得邀请码，同事使用各自账号加入。密码至少8位。页面身份与新增操作记录统一显示账号，所有员工均可编辑项目规则，保存直接生效。实际账号保存在所配置的数据库，仓库不包含预设密码。

上面的 Windows 命令使用 `npm.cmd`，避免 PowerShell 把 `npm` 解析为被执行策略拦截的 `npm.ps1`；其他系统使用 `npm start`。这种方式在前台运行，需要保持终端开启。

Windows 后台启动，在项目目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

`start.ps1` 检查本机服务是否已启动，否则在后台启动并打开网页；确认页面可访问后可关闭终端。停止时使用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\stop.ps1`，只停止此项目启动脚本记录且校验过的进程。

所有 PowerShell 脚本必须保存为 **UTF-8 with BOM**，`.editorconfig` 已设置该要求。Windows PowerShell 5.1 会把没有 BOM 的中文脚本按本机旧编码读取，可能出现乱码和“字符串缺少终止符”。这类解析错误发生在 Node 启动之前，应先修复脚本编码。自启动设置和排查方法见 [交接文件第1节](HANDOFF.md#1-在新电脑恢复开发)。

新工作空间的学生档案为空，不自动生成测试学生。更新现有工作空间时保留所有学生、匹配记录、账号、招生规则、版本和上传资料：

```powershell
cd "C:\Users\Administrator\Documents\ChatGPT\SGUREAD\sgu"
git pull --ff-only --autostash origin main
if ($LASTEXITCODE -eq 0) {
    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\apply-school-update.ps1
}
```

`apply-school-update.ps1` 只停止已登记的 SGU 后台进程、重新启动并检查服务，不执行学生清理。若旧服务是在 `npm.cmd start` 的终端中运行，先在那个终端按 Ctrl+C；更新脚本不会强停未登记的进程。

此脚本按现有默认 3210 端口运行；自定义部署按原方式重启即可。不要在更新流程执行历史学生清理工具。Git 同步只更新源码，不会直接修改另一台电脑的数据库。

## 已实现的工作流

| 模块 | 功能 |
|---|---|
| 学生与匹配 | 团队档案、分步录入、文本整理、多次考试、四类资格结果、条件级解释、模拟目标分数、材料准备、候选组合及匹配历史 |
| 条件问答 | 考试／分数、入学期、专业、学术考试、面试、豁免、材料及学费查询；先展示条件，关键歧义须澄清；每个答案带具体项目及证据 |
| 学校与项目 | 学校列表→学校总览→项目详情；资格可否矩阵、共同要求与适用项目、独立特殊要求、完整语言门槛、紧凑轮次和原始PDF |
| 资料维护 | 上传即自动提取并由OpenAI整理学校、年份及完整项目规则；集中高亮疑点，一次整体确认全部项目入库 |
| 修改记录 | 修改人、时间、前后差异、并发冲突检测、单项目完整版本回档；回档产生新版本 |

初始项目规则中的教育背景与部分豁免条件采用“员工已核实／否／待核实”状态，不能仅由国籍或课程名称推断。详细边界见 [架构与判定规则](docs/architecture.md)。

学校总览按招生年度和通道隔离，归并共同要求，并明确每条适用的项目；特殊条件单独列出。学校与项目详情均采用统一的学制／资格可否矩阵和完整成绩表，默认面向中国籍／日本籍申请人。关键路径、认证机构、年龄、总分与单项要求直接展示；豁免名称及适用项目集中于语言区域，完整条件与证明要求通过名称旁ⓘ悬停、键盘聚焦或点击查看。材料说明也使用同样的提示。详细原文链接默认关闭，可在“原文与版本”开启；完整PDF始终可用。学历取得节点合并到申请轮次；每轮一行，初筛、面试、最终结果分别一列。没有后续要求的项目不显示空栏。

所有学校和项目共用资格目录，分为“学历与教育经历”“课程体系与毕业资格”“学校认证与其他资格”三个并行维度。高中教育与预备教育、MEXT认定／指定课程、副学士等按组展示；A-Level、French Baccalaureate保留原始名称和资格阶段；六个常见认证机构合并为“认证机构”，其他认证机构单独列出并同步至统一目录。展示归组不合并后台条件，学校认证仍须结合课程范围、教育年限及完成状态核对。

资格矩阵用“可／N项可”“否”“待核”区分列明可用、明确排除和信息不足，备注直接指出组内哪些子项可用、不可用或待核；未列明不等于不接受，也不否决经其他完整路径申请。附加条件保持原字号并单行显示，过长内容省略；名称旁或行尾的“!”支持悬停、键盘聚焦或点击，查看各子项的完整条件、适用项目和原文依据。匹配继续按路径间“或”、路径内“且”判断，并保留命中依据及待核事项。

学校与项目详情的语言成绩表每条要求仅占一行：考试名称列按内容收窄，最低分显示为“≥ 72（总分）”，SAT／ACT单项和TOEIC听读合计保留各自口径。量表、考试日期和精简补充说明统一在最右侧“备注”列；完整原措辞保留在备注悬停提示中。窄屏在表格内横向滚动，不截断分数或增加行高。

## 语言理解

默认提供本地条件解析，可直接查询如：

- “不需要SAT或ACT，雅思6分能考虑哪些项目？”
- “2027年9月不需要面试的项目”
- “只有托福成绩能申请的学校”（先澄清含义）
- “各项目的学费是多少？”（当前资料返回未注明）

本地解析不是通用大模型。无法处理的精细问题会明确提示，不将未识别条件静默丢弃。可在`.env`设置`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`接入支持JSON输出的OpenAI兼容Chat Completions接口。只有问题文本会提交给配置的服务；项目答案仍由已核对的数据库规则生成。模型不可用时回退本地解析并提示核对。没有配置凭据时不会调用外部模型。

## 线上PDF解析

Docker镜像包含Poppler，默认`PDF_PARSER=cloud`。文字PDF由服务端直接提取；空文字层、编码异常或包含较大图片的页面，通过已配置的OpenAI模型逐页识别，防止遗漏扫描表格。物理页码由服务器生成，保留空白页位置；识别疑点带页码进入现有高亮核对区，不增加逐条确认步骤。

完整文件才保存提取结果。页数不一致、识别中断、截断或拒答均不会冒充处理完成；原PDF始终保留在Supabase。缺少模型密钥时等待配置，保存后自动继续。重新部署可从共享队列恢复任务，已提取全文继续复用。PDF文件输入使用[OpenAI官方接口](https://developers.openai.com/api/docs/guides/file-inputs)，`store:false`；仅发送需要识别的招生页面，不发送学生档案。

### 旧本机MinerU兼容方式（可选）

复制`.env.example`为`.env`，配置已安装的可执行文件。Windows示例：

```dotenv
MINERU_BIN=D:/AI-Yang.cn/tools/mineru/uv-tools/mineru/Scripts/mineru.exe
MINERU_HOME=D:/AI-Yang.cn/tools/mineru/data
MINERU_MODEL_BASE_DIR=D:/AI-Yang.cn/tools/mineru/models
MINERU_BIN_DIR=D:/AI-Yang.cn/tools/mineru/bin
```

上传PDF后自动检查本机MinerU服务；未运行时启动一次并等待本机标准解析引擎就绪。已运行的服务直接复用，不会停止或重启其他项目共用的服务。首次启动引擎最多等待3分钟，解析最多等待10分钟；后台任务未完成时继续等待同一任务。始终使用本地standard解析，不添加`--remote`。TXT／Markdown直接读取。已提取原文可在模型重试时复用，不截断长文档，不把未完成的结果当作完整资料。

通用模型的配置与本机MinerU相互独立；MinerU视觉模型不等于通用问答模型。

## 上传、核对疑点、整体入库

管理员在“团队设置 → 文档自动整理 · OpenAI”保存一次API密钥与模型。默认模型为 `gpt-6.1-sol`，使用官方 Responses API 严格结构化输出与流式接收；只有完成事件及结构校验都通过后才生成可入库草稿。请求设置 `store:false`，仅发送招生文档及核对意见，不发送学生档案。Windows会沿用已启用的系统HTTP代理，环境变量代理优先，本机连接绕过代理。

1. **上传文件**：自动排队、提取全文，识别学校、年份、项目、通道，整理资格、成绩、豁免、日期、材料及完整条款。缺少配置时保留原文，保存配置后自动继续。
2. **核对疑点**：黄色显示疑点、原文短引及与已入库规则的变化，完整规则可展开查看。需要修正时填写核对意见，系统重新整理，无须手工建项目或逐条录规则。
3. **整体确认入库**：一个按钮确认本文件全部项目；项目、历史版本、来源、确认人及文件状态在同一事务提交。并发修改返回冲突，重复点击不重复入库。不同学校、年度和通道相互隔离。

缺失信息保留 `null` 或“未注明”，不默认两年有效期、指定入学日或零分门槛。无法可靠映射的复杂条件仍完整展示，自动匹配保留待核实。关键归属不明、矛盾日期、补充通知替换完整手册等问题会高亮并要求先修正；不是每个空值都阻止入库。

过去仅建立空白壳的草稿保存原副本后自动整理，已有实质规则的人工草稿不被覆盖。列表与详情自动同步。网络传输中断自动重试一次，仍失败时保留原文和上次整理结果。

接口依据：[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)、[流式响应](https://developers.openai.com/api/docs/guides/streaming-responses)、[Node.js代理支持](https://nodejs.org/download/release/latest-v24.x/docs/api/http.html#httpsetglobalproxyfromenvproxyenv)。

## 数据与协作

- Railway配置`DATABASE_URL`连接Supabase数据库的私有`sgu` schema，作为正式数据来源。原有账号、会话、学生、项目、规则版本、匹配快照和审计记录完整保存；`files`表保存原文件和提取文本并校验SHA-256，`settings`表保存OpenAI配置。云端重新部署不依赖实例磁盘保留这些内容。
- 未配置`DATABASE_URL`：继续读取原有`.data/sgu.db`、`.data/uploads/`和`.data/openai.json`。连接已配置但失败时停止启动，绝不静默退回空SQLite库。
- Supabase使用Session pooler（5432），启用并验证TLS证书；应用schema启用RLS，拒绝`PUBLIC`、`anon`和`authenticated`访问。密码与密钥只供后端使用，不回传页面、日志或业务JSON导出。
- `.env`、`.data/`、`.qa/`及本机解析缓存`blobs/`、服务锁文件均在`.gitignore`中；仓库只存程序、公开招生资料与隔离的自动测试夹具，测试学生不会进入正式初始化。
- 应定期备份数据库及原文件。“团队设置”可导出业务JSON（不含密码和登录会话）。SQLite完整恢复需复制完整数据目录；Supabase应备份私有`sgu` schema，包含`files`和`settings`。
- `apply-school-update.ps1` 仅重启并检查服务，不再清空学生档案、匹配记录或操作历史。普通启动同样保留现有数据。
- 共享写事务串行化并检查版本，过期修改返回409；文档任务使用数据库锁防止滚动部署时重复整理。Railway独立处理PDF和模型整理，期间可以关闭网页或个人电脑。未配置DATABASE_URL时各自SQLite仍独立，仅供兼容运行。

已有SQLite资料不会因填写连接地址自动上传。首次迁移用`scripts/migrate-database.mjs`：先保存线上只读快照，再合并本地只读快照，默认仅预览；显式`--apply`才写入目标。线上同名账号和密码优先、原会话保留；相同项目版本内容必须一致才允许补齐后续版本，冲突会中止。整个导入在一个事务内完成，重复执行不会重复创建记录。备份包含凭据，只能存放于忽略的私有目录。

用户已授权常规更新直接上线；以Railway运行结果验收，不要求本机同步运行。代码发布不覆盖已有业务记录。

Railway部署未设置`APP_ORIGIN`时，程序使用平台提供的`RAILWAY_PUBLIC_DOMAIN`识别正式HTTPS地址，避免将正常提交误判为跨站请求（[平台变量说明](https://docs.railway.com/variables/reference)）。独立反向代理或其他自定义域名应将`APP_ORIGIN`设为实际访问地址，例如`https://school.example`；不包含页面路径。HTTPS会话自动设置Secure Cookie，仍保留来源、JSON请求标识和CSRF校验。开发默认使用本机HTTP地址，不信任客户端传入的转发头。

项目还提供Dockerfile及compose示例：

```sh
docker compose up -d --build
```

默认容器映射到服务器本地3210端口；正式部署配置DATABASE_URL，外部访问由部署方的反向代理承担。镜像已包含线上PDF解析组件，无需连接Windows路径。

## 范围

本版判断已收录的公开申请条件，不计算录取概率。`未注明`、`学生未填写`、`明确不要求`、`明确不接受`保持区分。新的学校、招生通道或年度通过独立项目记录维护；请勿直接把旧年度条件迁移成新年度事实。自动提取仍需人工核对，高级复杂条件通过“完整规则结构”维护。
