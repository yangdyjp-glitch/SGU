# SGU 日本本科选校工作台

换电脑或接续开发，请先阅读 [开发交接 HANDOFF.md](HANDOFF.md)。

面向公司升学顾问的内部工作台。三个入口共用一套经核对的项目规则：学生匹配、条件问答、学校与项目浏览；同时提供资料维护、团队共享、修改记录和版本回档。

首期内置立命馆大学 2027 AO 英语本科 GLA、JDP、GS、CRPS、ISSE 五个项目，28条语言考试／版本门槛和11组申请轮次。资料来自用户提供的23页手册及已核对的135条分析记录。原文及关键词库随源码提供，真实学生数据不会写入Git。

## 运行

需要 **Node.js 24.15或以上**，使用Node原生HTTP、SQLite和浏览器ES模块，无第三方运行依赖、无构建步骤。

```powershell
git clone https://github.com/yangdyjp-glitch/SGU.git
cd SGU
npm.cmd start
```

访问 **http://127.0.0.1:3210**。首次打开使用账号和密码创建管理员，不再填写姓名；随后在“团队设置”取得邀请码，同事使用各自账号加入。密码至少8位。页面身份与新增操作记录统一显示账号，所有员工均可编辑项目规则，保存直接生效。实际账号保存在本机数据库，仓库不包含预设密码。

上面的 Windows 命令使用 `npm.cmd`，避免 PowerShell 把 `npm` 解析为被执行策略拦截的 `npm.ps1`；其他系统使用 `npm start`。这种方式在前台运行，需要保持终端开启。

Windows 后台启动，在项目目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

`start.ps1` 检查本机服务是否已启动，否则在后台启动并打开网页；确认页面可访问后可关闭终端。停止时使用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\stop.ps1`，只停止此项目启动脚本记录且校验过的进程。

所有 PowerShell 脚本必须保存为 **UTF-8 with BOM**，`.editorconfig` 已设置该要求。Windows PowerShell 5.1 会把没有 BOM 的中文脚本按本机旧编码读取，可能出现乱码和“字符串缺少终止符”。这类解析错误发生在 Node 启动之前，应先修复脚本编码。自启动设置和排查方法见 [交接文件第1节](HANDOFF.md#1-在新电脑恢复开发)。

新工作空间的学生档案为空，不再自动生成测试学生。旧工作空间本次需执行一次清理，保留原账号、招生规则、版本和上传资料：

```powershell
cd "C:\Users\Administrator\Documents\ChatGPT\SGUREAD\sgu"
git pull --ff-only --autostash origin main
if ($LASTEXITCODE -eq 0) {
    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\apply-school-update.ps1
}
```

`apply-school-update.ps1` 停止已记录的 SGU 后台进程，先备份完整 SQLite 数据库，再清空**全部学生、匹配快照和学生／匹配操作记录**，最后重新后台启动。备份位置显示在终端，默认在 `.data/backups/`。重复执行会跳过清理，保护本次更新后新建的学生。普通启动不会触发清空。若旧服务是在 `npm.cmd start` 的终端中运行，先在那个终端按 Ctrl+C；更新脚本不会强停未登记的进程。

此脚本按现有默认 3210 端口运行；自定义部署请先停服，再在项目目录执行 `npm.cmd run students:clear`，随后按原方式启动。清理会读取 `.env` 中的 `DATA_DIR`。Git 同步只更新源码，不会直接修改另一台电脑的数据库。

## 已实现的工作流

| 模块 | 功能 |
|---|---|
| 学生与匹配 | 团队档案、分步录入、文本整理、多次考试、四类资格结果、条件级解释、模拟目标分数、材料准备、候选组合及匹配历史 |
| 条件问答 | 考试／分数、入学期、专业、学术考试、面试、豁免、材料及学费查询；先展示条件，关键歧义须澄清；每个答案带具体项目及证据 |
| 学校与项目 | 学校列表→学校总览→项目详情；资格可否矩阵、共同要求与适用项目、独立特殊要求、完整语言门槛、紧凑轮次和原始PDF |
| 资料维护 | PDF／TXT／Markdown上传、本机MinerU解析、关键词定位建议、员工核对后编辑规则、复制为新项目 |
| 修改记录 | 修改人、时间、前后差异、并发冲突检测、单项目完整版本回档；回档产生新版本 |

初始项目规则中的教育背景与部分豁免条件采用“员工已核实／否／待核实”状态，不能仅由国籍或课程名称推断。详细边界见 [架构与判定规则](docs/architecture.md)。

学校总览按招生年度和通道隔离，归并共同要求，并明确每条适用的项目；特殊条件单独列出。学校与项目详情均采用统一的学制／资格可否矩阵和完整成绩表，默认面向中国籍／日本籍申请人。关键路径、认证机构、年龄、总分与单项要求直接展示；重复豁免信息集中于语言区域。材料名称旁的ⓘ支持停留、键盘聚焦或点击查看细则。详细原文链接默认关闭，可在“原文与版本”开启；完整PDF始终可用。学历取得节点合并到申请轮次；每轮一行，初筛、面试、最终结果分别一列。没有后续要求的项目不显示空栏。

资格目录分别列出十二年课程、MEXT课程、六个认证机构、IB、不同A-Level资格、OSSD、DSE等，随当前已核对规则中的新资格扩充。按用户指定，立命馆未列明的OSSD／DSE显示“否”；这里表示未列为独立资格，不自动否决持有人经十二年课程等通用路径申请。附加条件、年龄限制和明确排除仍保留，实际匹配引擎继续逐条判断。

## 语言理解

默认提供本地条件解析，可直接查询如：

- “不需要SAT或ACT，雅思6分能考虑哪些项目？”
- “2027年9月不需要面试的项目”
- “只有托福成绩能申请的学校”（先澄清含义）
- “各项目的学费是多少？”（当前资料返回未注明）

本地解析不是通用大模型。无法处理的精细问题会明确提示，不将未识别条件静默丢弃。可在`.env`设置`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`接入支持JSON输出的OpenAI兼容Chat Completions接口。只有问题文本会提交给配置的服务；项目答案仍由已核对的数据库规则生成。模型不可用时回退本地解析并提示核对。没有配置凭据时不会调用外部模型。

## 本机MinerU

复制`.env.example`为`.env`，配置已安装的可执行文件。Windows示例：

```dotenv
MINERU_BIN=D:/AI-Yang.cn/tools/mineru/uv-tools/mineru/Scripts/mineru.exe
MINERU_HOME=D:/AI-Yang.cn/tools/mineru/data
MINERU_MODEL_BASE_DIR=D:/AI-Yang.cn/tools/mineru/models
MINERU_BIN_DIR=D:/AI-Yang.cn/tools/mineru/bin
```

先通过原MinerU安装目录的`mineru.cmd server start`启动解析服务，再启动本网站。上传PDF后点击“本机解析并提取建议”。始终使用本地standard解析，不添加`--remote`。TXT／Markdown直接读取。提取结果不会自动写入项目规则；定位行号也不冒充PDF页码。PDF解析失败保留原文件并显示重试入口。

通用模型的配置与本机MinerU相互独立；MinerU视觉模型不等于通用问答模型。

## 数据与协作

- `.data/sgu.db`：SQLite数据库，包含员工、会话、学生、项目当前版本、历史规则、匹配快照和操作记录。
- `.data/uploads/`：员工上传的原始文件及提取文本。
- `.env`、`.data/`、`.qa/`均在`.gitignore`中；仓库只存程序、公开招生资料与隔离的自动测试夹具，测试学生不会进入正式初始化。
- `.data/`与上传文件应定期备份。“团队设置”可导出数据JSON（不含密码和登录会话）；完整恢复以停服复制整个`.data/`为准。
- 多人须访问**同一台服务器**。每个人自行运行一份程序会得到独立数据，不会自动跨机器同步。

团队部署时，先在本机完成首个账号设置，再通过HTTPS反向代理提供内部地址，并设置`APP_ORIGIN`与`COOKIE_SECURE=true`。开发默认只绑定`127.0.0.1`。提供Dockerfile及compose示例，但本仓库提交本身不会部署公网服务。

```sh
docker compose up -d --build
```

默认容器映射到服务器本地3210端口，数据存入具名卷；外部访问由部署方的反向代理承担。容器内使用MinerU需要另行配置本地可执行环境，不自动连接Windows路径。

## 验证

```sh
npm run check
npm test
```

测试覆盖多学历路径与年龄范围、TOEFL版本及单项、有效期、禁止拼分、豁免未知、预毕业、材料与资格分离、JST截止、组合申请、保守查询、身份验证、并发写入冲突、版本回档和历史不变性。浏览器验收记录见 [验证记录](docs/verification.md)。

## 范围

本版判断已收录的公开申请条件，不计算录取概率。`未注明`、`学生未填写`、`明确不要求`、`明确不接受`保持区分。新的学校、招生通道或年度通过独立项目记录维护；请勿直接把旧年度条件迁移成新年度事实。自动提取仍需人工核对，高级复杂条件通过“完整规则结构”维护。
